# 未匹配音频人工复核

本工具只生成独立复核页面，不改动听写网站、词表映射或已验收音频。
所有候选的`approved`均为false；文字相似度只用于排序，不作为匹配概率。

## 分类依据

严格对齐中最近的前后已匹配词作为锚点，只在它们之间寻找候选；不在整本书中
搜索相似词后强行移用。每个未匹配词只归入一个分类：

1. **空格／标点形式差异**：首次或重试识别文本去除空格、标点后与目标吻合。
   仍需听感确认，不能泛化为所有相似拼写都正确，例如in visible与invisible。
2. **重试吻合，但可能夹带其他词**：单段重试准确，但首次识别有更多词。
   可能只是识别幻觉，也可能片段包含额外发音，不能只接受其中一个词。
3. **有相近识别文本**：规范化字符的SequenceMatcher比值达到0.6；是候选线索，
   不是置信概率，不保证同音、同义、单复数正确。
4. **仅顺序定位到一个片段**：一个待匹配词、一个独立片段，尚无充分文本证据。
5. **区间内有片段，尚无目标词线索**：多个待定位词共享区间，且该词无充分文本线索。
6. **前后锚点间无独立片段**：没有已检测的独立片段。可能是词表与录音版本差异、
   切分遗漏等，不能证明整份录音中不存在该词。

前三类按文本证据排序显示区间内全部候选，不自动选定第一项。
前后词对照片段用于定位，不允许作为单词直接确认。

## 生成与使用

```sh
PYTHONDONTWRITEBYTECODE=1 python3 scripts/review_local_pronunciation.py
```

程序复用既有识别缓存，不再运行识别模型；检查原文件SHA256、复核队列与原370项
一致，然后直接复制原MP3音频包，并复用原始音频包及PCM一致性校验。
输出在`.data/local-pronunciation/review`（不提交音频到Git）：

- `index.html`：可听、可筛选、每批10项的复核页面。
- `summary.md`：分类计数。
- `review-classification.csv`：逐词分类与两次识别文本。
- `review-reuse-suggestions.csv`：同词且非空英音音标完全相同的已验收音频复用建议，
  优先同书，找不到同书才建议跨书；只是当前待匹配项的子集，这些复用建议尚未发布。
- `review-report.json`：候选源文件指纹、原始区间、稳定片段ID和统计。
- `clips/`：原音质候选及前后对照片段。

开发服务运行时，可打开Vite已有的`/@fs/`路径访问项目内的HTML，无须增加服务器。
默认先显示空格／标点差异类，方便小批量确认。页面只有本地浏览器进度存储，
不上传确认记录；应点击“导出确认结果”备份并交给开发者合并。
导出包含报告指纹、目标词ID、选择的片段ID及明确确认／不匹配／不确定状态。
同一片段不能同时确认给两个不同目标词。
若对照里能听到目标词，但独立候选缺失或切分不对，可以标记“需重新切分”，
导出后由开发者重新定位；这不会把包含前后词的整段对照音频错误发布为目标词。

确认结果**不会自动发布**。后续合并时应重新校验报告及源文件指纹、确认片段的
完整性和原音质，发布前后对比词表及运行播放回归测试。

## 利用顺序减少人工核对

只处理“一项待匹配词、一个候选片段、同录音内两个明确前后锚点”的顺序类。
先用已有tiny.en/base.en离线模型单段识别，再用已有small.en识别包含前后词的
对照片段。全部识别都不提供目标词提示。按时间戳提取前词、目标词、后词：
必须三项文本完整吻合，或两个单段模型均完整吻合；不能只凭顺序、模糊拼写或
单复数差异自动接受。不同模型仍属于Whisper体系，不视为绝对独立的证明。

```sh
PYTHONDONTWRITEBYTECODE=1 uv --offline run --with faster-whisper python scripts/refine_ordered_pronunciation.py \
  --stage analyze --tiny-model "$TINY_MODEL" --base-model "$BASE_MODEL" --context-model "$SMALL_MODEL"
PYTHONDONTWRITEBYTECODE=1 python3 scripts/refine_ordered_pronunciation.py --stage publish
```

三个变量指向本机已有模型快照；不下载新模型、不调用付费接口。结果逐项缓存到
`.data/local-pronunciation/ordered-refinement.json`，含模型路径、片段及源文件指纹、
识别结果和时间戳。发布前复核原音频包和PCM；仅增加已通过项的`localAudio`。
原始批量导入重新发布时，需要再执行该优化的发布阶段，复用缓存恢复优化映射。

生成新版复核页面时，从未改变的原始候选计算报告指纹，而不是从缩短后的待核对
队列计算，避免丢失浏览器保存的人工进度。自动处理项从队列移除，但已有浏览器
记录保留，导出仍包含原记录；计数只计算当前待核对项。

## 后续可减少人工工作的手段

- 在小批量听感确认后，为已验证的表达形式差异增加有边界的白名单规则。
  不应直接把所有空格、单复数或相似拼写差异都自动接受。
- 优先复用同书已验收同词、同英音音标的音频，减少按位置一对一匹配遗漏的重复词。
  其他书也有同词时，可在接受跨书复用后使用；不同读音或音标未知时不直接合并。
- 对相近文本类使用不同或更准确的识别模型交叉验证，只处理异常片段；
  新模型的下载、运行时间和CPU开销需要单独评估，不应重跑全部录音。
- 对无独立片段类检查前后对照，再核对原书词表版本或调整局部静音切分阈值。
  不应先用目标词提示模型再把输出当作独立验证证据。

## 用户授权的候选一暂用策略

在用户抽样听辨并明确授权后，剩余352项中315项有独立候选，先采用复核页面的
候选一。37项没有独立候选，仍走原来的在线／系统发音，绝不把前后对照整段当成
目标词。不运行新识别、不重新编码；重新检查原文件指纹、音频包及PCM一致性，
再复制既有原音质候选。仅改词书的`localAudio`和`localAudioUncertain: true`。

```sh
PYTHONDONTWRITEBYTECODE=1 python3 scripts/publish_candidate_pronunciation.py
```

听写页面在这些词下方显示低干扰标签“发音可能有误”。报告中保持`unmatched`，
增加`method: first-candidate-user-policy`、所选片段ID及质量验收结果：音质已验证
不等于内容已确认。`totals.provisional`单列暂用数量，`fallback`只统计未接入本地
音频的词；`matched`仍只包含可靠匹配。暂用候选不进入已验收同词复用建议。

复核页面保留352项及原报告指纹／浏览器人工记录，并标记“候选一已暂用”。
人工确认与不匹配标记仍需导出后合并，不会实时改变听写音频。部分词的候选一
共享同一个片段，当前仅按用户的暂用策略接入，不能据此同时认定多个目标已确认。
原始批量导入重新发布后，依次恢复顺序优化、候选一暂用映射。

本次验证：Python 48/48、Node 6/6、本地发音／复核浏览器测试37/37；其中逐一
检查315项接口响应为本地来源且字节与候选一完全一致。另检查29份原文件指纹、
315项词表差异边界、实际播放进度及切词标签显示。构建成功，lint无错误（6项
既有警告）。类型检查仍有4项既有错误：`src/utils/mixpanel.ts`第130／175行
读取不存在的`isWordVisible`，`src/utils/trackEvent.ts`第9／11行缺少`window.gtag`
类型；在未修改的HEAD副本中复现了相同4项错误，没有为此改动无关代码。
